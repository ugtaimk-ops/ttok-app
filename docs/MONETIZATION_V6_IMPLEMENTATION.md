# 똑 수익화 v6 코드 준비 현황

작성일: 2026-11-14. **운영 배포 및 과금 활성화 전 검토용**이다.

## 기존 구조와 충돌

- 기존 Android 앱 ID는 `com.ttokapp.app`이며 결제는 RevenueCat Capacitor SDK가 처리한다. 서버는 RevenueCat 비밀키 조회와 웹훅으로 `users/{uid}.isPremium`을 기록한다.
- 기존 무료는 KST 월 30회, Pro는 KST 월 100회다. 기존 Pro 월간·연간 상품은 `ttok_pro_monthly`, `ttok_pro_yearly`다. 기존 구매자에게 새 Pro 50회를 적용하면 혜택이 줄어든다.
- 새 요금제에는 별도 결제 주기, 요청별 차감, 광고 보상 잔액이 필요하므로 단일 `aiUsageCount` 필드로 표현할 수 없다.
- 똑타임 공유 목표·친구 연동은 이전 합의에 따라 제외 상태를 유지했다. 이번 변경에서 이를 다시 켜지 않았다.

## 구현된 로컬 코드

- 순수 이용권 엔진: 무료 KST 일 1회, Basic 30회, 신규 Pro 50회, Plus 70회, Pro 합산 80/120회, 기존 Pro 100회/월, 구독별 기간·만료순 차감, 예약/확정/환불, 보상 일 5회 상한.
- 기존 Pro 연간 구독도 **매달 100회**로 갱신한다. 최초 이전 시 같은 KST 월에 사용한 횟수를 승계한다.
- 새 서버 전용 Firestore 문서 `users/{uid}/monetization/v6`에 사용량을 트랜잭션으로 저장한다. 해당 문서의 클라이언트 쓰기는 두 규칙 파일에서 차단한다.
- RevenueCat 비밀키 조회 결과에서 허용한 Play 상품만 구독으로 반영한다. 취소 후 유효기간이 남은 구독은 유지하고, 만료·환불 상품은 제외한다. 클라이언트의 구독 주장으로 권한을 올리지 않는다.
- AI 요청 헤더에 요청 ID를 넣고 서버에서 중복 차감을 막는다. 기존 앱을 위한 임시 ID 생성은 요청 재시도 사이 멱등성이 보장되지 않으므로 새 앱 버전 배포가 필요하다.
- 설정 화면에서 새 상태를 구독별 남은 횟수와 광고 보상으로 구분해 보여 준다. 구매 화면은 기존 월간·연간 Pro 화면 대신 Basic·Pro v2·Plus 세 상품을 사용한다. 새 이용권 상태(`aiQuota`)가 서버에서 확인된 후에만 결제 버튼이 활성화된다.
- 로컬 웹과 UI 편집기에서는 Play 상품 조회 없이 세 요금제 화면을 열 수 있다. 이 화면은 미리보기이며 결제 버튼은 비활성이다. Play 구매 테스트는 Android 앱에서만 가능하다.
- Pro 홈에 똑타임 `dailyStats`로 계산한 오늘·이번 주·이번 달 공부 시간, 최다 과목, 전주 비교와 주간 기록 기반 다음 주 연습량을 추가했다. 읽기 권한이 없으면 오류를 표시하고 임의 데이터를 만들지 않는다.
- AdMob SSV 서명 검증, 서버 발급 nonce, `transaction_id` 전역 중복 방지, 광고 단위·보상 유형·시각·일일 상한 검사 코드를 추가했다. 실제 광고 노출 기능은 **비활성**이다.

## 기능 플래그와 데이터 이전

`MONETIZATION_V6_ENABLED=true`일 때만 새 사용량 경로와 광고 보상 엔드포인트가 동작한다. 기본값은 꺼짐이며, 기존 30/100회 정책과 구매 UI가 유지된다. 기존 Firestore 문서나 계정은 삭제하지 않았다.

처음 활성화할 때 서버는 RevenueCat 비밀키로 구독을 확인한다. 기존 Pro는 이전 `aiUsageMonth`가 현재 KST 월과 같을 때만 `aiUsageCount`를 승계한다. 새 문서는 추가형이다. 운영 전체 데이터 마이그레이션은 수행하지 않았다.

## 새 상품 ID 제안

| 플랜 | 새 Play 상품 ID | 목표 가격 | 이용권 |
|---|---|---:|---:|
| AI Basic | `ttok_ai_basic_monthly` | 월 1,900원 | 결제 주기당 30회 |
| 똑 Pro v2 | `ttok_pro_v2_monthly` | 월 3,900원 | 결제 주기당 50회 |
| AI Plus | `ttok_ai_plus_monthly` | 월 3,900원 | 결제 주기당 70회 |

기존 Pro 상품 ID·가격·권한은 그대로 둔다. 2026-11-14 RevenueCat `ddok_v6` 오퍼링 화면에서 세 패키지의 상품 ID와 기본 요금제 연결을 확인했다. 실제 가격, entitlement 연결 및 Play Console의 판매 상태는 아직 확인하지 못했다. Basic과 Plus의 동시 결제 제한은 화면과 서버 이용권 계산에 들어갔지만, 매장 수준의 구매 차단은 Play/RevenueCat 상품 구조 확인이 필요하다. 유료 이용권을 모두 소진해도 무료 일일 1회는 추가되지 않는다.

RevenueCat에서는 신규 Pro만 기존 `똑 Pro` entitlement에 연결한다. Basic과 Plus는 각각 별도 entitlement에 연결해야 한다. 기존 월간·연간 Pro를 Offering에서 숨기는 것은 가능하지만, 기존 구매자가 있다면 entitlement 연결은 유지해야 한다.

사용자는 기존 Pro 상품을 비활성화했고 신규 상품으로 교체했다고 보고했다. 신규 앱 코드에서는 구형 구매 화면과 구형 상품 직접 조회를 제거했다. 서버에는 기존 Pro 구독자의 권한 보존을 위한 판별 로직만 남겼다. 기존 구독이 있다면 동일한 Play 상품 ID·base plan으로 RevenueCat에 다시 가져와 `똑 Pro`에 연결해야 한다. 이미 배포된 앱에는 이 코드 변경이 적용되지 않는다.

## 필수 외부 설정과 미완료 항목

1. Play Console 대상 연령 및 Families/광고 정책, AdMob 아동 대상 설정과 동의 절차 확인. 현재 광고 SDK는 설치하지 않았고 배너·네이티브·보상형 동영상 노출이 없다.
2. 상품 3개·base plan·RevenueCat entitlement/offering 연결. 서버는 기존 RevenueCat 비밀키 조회로 검증하며 Google Play Developer API 직접 조회 및 RTDN 수신기는 아직 구현되지 않았다. 결제 확인·복원·갱신은 현재 RevenueCat 통합에 의존한다.
3. 광고 활성화 전 `ADMOB_REWARDED_AD_UNIT_ID`를 정확히 등록하고 SSV callback URL을 설정한다. 클라이언트 SDK와 실제 광고 단위는 아직 연결하지 않았다.
4. Pro 기능 6종 중 기존 AI 리포트와 새 주간 공부 리포트 일부만 있다. 시험 Pro 관리, 목표 자동 연동, 테마·위젯 옵션은 미완료다. 목표 자동 연동은 이전에 정한 목표 공유 제외 방침과 충돌하므로 별도 합의가 필요하다.
5. Firebase 운영 보안 규칙, Functions, Play 상품, 실제 광고, 스토어 앱 **어느 것도 배포하거나 활성화하지 않았다**.

## 검증과 위험

- 순수 이용권·상품 분류·SSV 서명 테스트 34개 통과. 기존 Pro와 신규 Pro가 동시에 조회될 때 기존 100회 혜택이 우선하는 경우, 광고 보상 이용권을 문제 풀이에만 쓰는 경우, Basic/Plus를 Pro entitlement에 잘못 연결해도 Pro 권한이 지급되지 않는 경우를 포함한다.
- `npm run lint`, `npm run build`, `npm run test:security`는 변경 중간 시점에 통과. 최종 수정 뒤 재실행 결과는 작업 완료 보고에 기재한다.
- Firestore emulator에서 `monetization` 본인 읽기·타인 읽기 거부·클라이언트 쓰기 거부 테스트 통과. 기존 공유학습 전체 emulator 테스트는 35/36 통과, `dailyStats` 실시간 수렴 테스트 하나가 30초 제한으로 실패했다. 이번 수익화 규칙과 별개지만 원인을 추적해야 한다.
- 실제 Google Play 결제, 광고 표시·SSV 실콜백, 실기기, 운영 Firebase/Render는 미검증이다.
- 광고 및 RevenueCat 조회가 추가되면 네트워크·Firestore·광고 서비스 사용량에 따른 비용이 발생할 수 있다. 예상 월 비용은 실사용량과 계약 요금제를 확인한 뒤 산정해야 한다.
- v6는 한 Firestore 문서에 사용자별 상태를 보관한다. 요청 기록을 48시간 후 정리하므로 그 이후 동일 요청 ID의 재사용은 차단하지 못한다. 서버 활성화 전에 장기 멱등성 저장 방식과 동시 사용 부하를 추가 검증해야 한다.

## 롤백

`MONETIZATION_V6_ENABLED`를 끄면 서버가 기존 30/100회 경로로 돌아간다. 이 경우 새 v6 사용량과 기존 월 카운터가 별도로 움직이므로, **운영 활성화 후 단순 플래그 롤백은 이용 횟수 증가 가능성**이 있다. 운영 활성화 전 백업·계정별 잔액 대조·롤백 절차 확정이 필요하다. 기존 Pro 상품은 수정하지 않는다.
