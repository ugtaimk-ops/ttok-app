# 똑 통합 개발 지시서: 1차 코드 조사와 크레딧 엔진

작성일: 2026-11-19. 원본 지시서: 사용자가 보낸 `똑(TTOK) 앱 전체 시스템 통합 개발 프롬프트`.

## 이번에 구현한 코드

- `services/creditPolicy.ts`: KST 일일 무료 지급, 검증된 유료 결제 주기별 지급, 잔액 합산, 요청 ID별 예약/확정/실패 반환, 예상보다 많이 쓴 요청의 미회수 금액 기록.
- Gemini `usageMetadata`의 입력·캐시·출력·추론 토큰으로 달러 기준 원가를 계산하고, 1크레딧 = 0.00001 USD 정책으로 올림. 모델별 요금은 JSON 서버 설정에서만 읽고, 누락된 모델·오디오 요금은 계산을 거부한다. 실제 운영 요금표는 공식 페이지와 대조해야 한다.
- `tests/credit-policy.test.mjs`: 자정, 구독 갱신·합산, 멱등성, 환불, 초과 사용, 캐시·추론 토큰, 오디오 미설정 시 거부를 검증한다.

## 왜 운영 경로에 아직 연결하지 않았는가

1. 기존 유료 사용자의 `aiUsageCount`와 v6의 결제 주기별 횟수를 v7 크레딧으로 바꾸는 계약이 아직 정해지지 않았다. 임의 환산은 이미 결제한 혜택을 줄일 수 있다.
2. `MONETIZATION_V6_ENABLED`는 기본 꺼짐이며, 운영 상품·가격·RevenueCat entitlement가 새 Free/Basic/Pro/Max와 일치하는지 확인되지 않았다. Plus 구독 권한은 별도로 존속시켜야 한다.
3. 가격표가 바뀌면 서버의 모델별 입력·출력·캐시·오디오 요금을 갱신해야 한다. 요금표 미설정 시 과소 차감되면 안 된다.
4. API 호출 전에 최대 출력 토큰과 입력 토큰으로 상한을 예약하고, 응답의 실제 usageMetadata로 정산할 서버 어댑터가 필요하다. 현재 Gemini 제공자는 문자열만 반환한다.
5. Firestore 트랜잭션 저장, 48시간 이후에도 유지되는 요청 멱등성, 만료 예약 복구, App Check, Firestore 규칙 검증이 필요하다.

## 데이터 이전 계획

- `users/{uid}` 및 기존 `users/{uid}/monetization/v6`는 수정하지 않는다.
- 새 `users/{uid}/aiWallet/main`, `creditGrants`, `creditTransactions`, `aiRequests`는 **추가형**으로 만든다. 서버 Admin SDK만 쓰고 클라이언트 직접 쓰기는 금지한다.
- 기존 Pro/Plus 구독자의 상품 ID, 결제 주기, 잔여 횟수는 서버가 RevenueCat에서 확인하고 원래 혜택으로 유지한다. v7 신규 상품으로 자동 전환하지 않는다.
- 계정별 백업, 샘플 계정 잔액 대조, 테스트 결제와 환불, 롤백 정책을 검증한 뒤 운영 전환한다. 규칙과 운영 데이터를 이번 작업에서 배포하거나 수정하지 않았다.

## 필요한 서버 설정 및 외부 설정

- 기존: `GEMINI_API_KEY` 또는 `GEMINI_API_KEYS`, `FIREBASE_SERVICE_ACCOUNT_KEY`, `REVENUECAT_SECRET_API_KEY`, `REVENUECAT_WEBHOOK_SECRET`.
- 후속: 모델별 정식 가격표 설정, v7 기능 플래그, Play/App Store 새 상품 ID와 entitlement, App Check, AdMob 앱/광고 단위·서버 검증, 운영 백업.
- 앱이 학생 대상이므로 연령대, 광고 동의 및 미성년자 보호 정책을 스토어 제출 전에 결정해야 한다.
- 실제 Apple 인앱결제/서명, Google Play 실구매, 광고 보상, 운영 Firebase 규칙은 이번 단계에서 검증하지 않았다.

## 검증 범위

- 새 크레딧 엔진 테스트 9개 통과.
- 현재 v6 상품 분류 테스트는 `tsx --test`로 7개 통과. Node 24의 기본 TS 로더는 확장자 없는 내부 import를 해석하지 못하므로 `node --test tests/ai-quota-products.test.mjs`는 실패한다.
- 앱 린트·빌드 결과는 이번 작업의 최종 보고를 참조한다.
