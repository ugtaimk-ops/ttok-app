# 똑 관리자 서버 시작 방법

현재 앱에는 별도의 새 서버를 만들 필요가 없다. 운영 API는 Render의 `https://ttok-backend.onrender.com`이고, 관리 화면은 같은 서버의 `/server-design`에 있다. 사용자 계정과 공부 자료는 Firebase Authentication/Firestore에, 구독 상태는 RevenueCat과 Firestore에 저장된다. 관리 화면은 이 서비스들을 읽기 전용으로 확인한다.

## 현재 확인된 상태 (2026-11-15)

- `/api/health`: HTTP 200. 응답의 버전 표시는 `1.0.26`이다. 이 값만으로 최신 코드가 배포됐다고 판단하지 않는다.
- `/api/admin/overview`: 인증 토큰 없이 HTTP 401. 관리 데이터가 공개되지 않는다.
- `/server-design`: HTTP 200. 브라우저에서 관리 UI를 열 수 있다.
- 새 요금제 서버 모드(`MONETIZATION_V6_ENABLED`)와 관리자 UID 허용 목록의 **운영 값은 아직 확인되지 않았다**.

## 관리자 계정 연결

1. Firebase Console의 프로젝트 `gen-lang-client-0685740024` → Authentication → 사용자에서 본인이 사용할 **기존 똑 계정의 UID**를 확인한다. 이메일 주소가 아니라 UID다.
2. Render의 `ttok-backend` 서비스 → Environment에서 `DASHBOARD_ADMIN_UIDS`를 추가하고 값으로 그 UID를 넣는다. 여러 명이면 쉼표로 구분한다. 이 값은 앱이나 GitHub 소스에 넣지 않는다.
3. Render의 저장 옵션 중 배포가 실행되는 옵션을 선택해야 서버가 새 환경변수를 읽는다. 운영 변경이므로 배포 전 기존 데이터 백업·현재 서버 버전·영향을 확인한다.
4. `https://ttok-backend.onrender.com/server-design`에서 같은 Firebase 계정으로 로그인한다. 현재 화면은 이메일/비밀번호 로그인만 제공한다. 관리 API는 Firebase ID 토큰과 UID 허용 목록을 모두 확인한다.
5. 관리 화면의 ‘관리 데이터 조회 서버’는 **운영 서버 · Render**로 선택한다. ‘이 컴퓨터의 서버’를 선택하면 로컬 개발 데이터와 연결된다.

로그인 후 `ADMIN_NOT_CONFIGURED`가 뜨면 2~3단계가 적용되지 않은 것이다. `ADMIN_FORBIDDEN`이면 로그인한 계정 UID와 Render에 저장한 UID가 다르다. `API_NOT_FOUND`이면 선택한 서버에 관리 API가 아직 배포되지 않았다. 비밀번호, Firebase 서비스 계정 JSON, RevenueCat 비밀키는 채팅이나 GitHub에 올리지 않는다.

## 새 결제 상품과 앱 배포

새 상품은 RevenueCat의 `ddok_v6` 오퍼링에 연결된 `ttok_ai_basic_monthly`, `ttok_pro_v2_monthly`, `ttok_ai_plus_monthly`다. 앱 코드는 이 오퍼링을 직접 조회한다. 서버의 새 이용권 코드와 Firestore 규칙을 배포하고 `MONETIZATION_V6_ENABLED=true`가 적용된 뒤에만 앱의 구매 버튼이 활성화된다. 관리 화면의 ‘결제’ 메뉴에서 ‘새 요금제 서버 적용’을 확인할 수 있다. 기존 Pro 구매자 권한 보존 로직은 남아 있다.

운영 서버 배포와 Play 테스트 트랙 게시 전에는 실제 가격·기본 요금제·entitlement 연결, 계정별 이용 횟수, 구매 복원, 취소/환불을 테스트 계정으로 확인한다. 관리자 화면은 읽기 전용이며 구독 가격이나 회원 데이터를 여기서 직접 바꾸지는 않는다.
